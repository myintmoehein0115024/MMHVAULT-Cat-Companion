# MMHVAULT-Cat-Companion · P2.3 头脸耳缘毛发统一（增量覆盖）

## 版本基线与禁改边界
- 开发使用用户上传的 P2.1 全量 ZIP，叠加上一轮 P2.2 的真实更新文件作为 P2.3 基线。
- **必须先部署 P2.2，再应用本包 P2.3**。本包不重复包含 P2.2 的 `js/fur-groom.js` 或 `js/renderer.js`；缺少这些依赖，P2.3 将无法正确启动。
- 仍加载不变的 `models/black-gold-cat-p21.glb`，未重新建模，也没有更换 GLB、骨骼、绑定、6 段动画、行为状态机。
- 不更改 MMHVAULT 主站、Life Planner、Supabase、财务数据、账户、登录或部署地址。

## P2.3 真正修改的内容
1. **新增 `js/face-fur.js`**：用 GLB 原生网格的顶点、法线、顶点色和三角形面积分布生成局部刚性短绒片。分别作用于 `HeadCore`、`HeadLower`、两侧 `Cheek`、两侧 `EarShell`、`ChestRuffP12` 与 `P18SoftNeckRuffNode` 共 8 个已有节点。每组基础层＋细节层，合计 7,630 片小三角毛片（不是 7,630 根真实毛发）。
2. **面部避让**：头部中央眼鼻口区域尽量不生成新毛片；耳朵使用耳壳顶点颜色和法线作筛选，只给深色外耳、耳缘增加短绒，避免遮盖粉色内耳。当前是程序化区域掩膜，具体边界需实际 GPU 实机观察。
3. **节点运动同步**：新短绒采用来源网格的局部坐标，与头、脸颊、耳壳及颈胸原有矩阵一同运动；不错误地套用身体骨骼的 skin palette。P2.2 身体/尾巴绒毛继续使用 GPU skin。
4. **手机降级**：页面画布宽度低于 620 CSS 像素时仅绘制每组基本短绒层；桌面可绘制基本层＋细节层。新增额外 GPU 绘制与显存开销，尚需真机长时间监测。
5. **页面文案／缓存键**：`index.html`、`js/app.js` 切换到 P2.3 资源版本；实际 GLB 地址不变。

### 没有做的改动
- **未替换**旧 `HeadFur`／`HeadGoldOutline`／`P16HeadSoftSilhouette` 等造型资产，以免在没有可靠实机画面时误改已确认的猫脸轮廓。
- **未做** Blender 专业拓扑、UV／PBR 贴图、真实毛发物理、透明毛卡、骨骼重绑或新动画片段。因此不能称为电影级毛发完成版。

## 执行过的测试与结果
- `node --check js/face-fur.js js/glb-renderer.js js/app.js`：逐个检查通过。
- `node tools/check-p22-fur.mjs`：P2.2 身体、尾巴骨骼蒙皮、索引、6段动画离线检查通过。
- `node tools/check-p23-face-fur.mjs`：8 个局部来源节点存在，16 组新毛发网格正常生成，顶点索引及有限值正常，原 2 套 skin／六段动画存在。
- `node tools/check-p23-renderer-mock.mjs`：画布宽 420／1200 模拟，5 组动作状态完成绘制调用，相关资源可释放；记录 400／460 次模拟绘制和约 10.16 MiB 的模拟 GPU 上传（不是显卡实际负载）。
- 使用 Chromium 对 320／375／390／650／768／844／1280／1440 CSS px **进行静态 HTML/CSS 布局检查**：未发现横向溢出；不是完整 WebGL 页面端到端测试。
- **无法完成 WebGL2 硬件/软件 GPU 实际画质验收**：运行环境无法创建 WebGL2 上下文且本地网页导航被环境安全策略阻止；因此 shader GPU 编译、正面/侧面绒毛视觉、iPhone/Android FPS、发热、穿模和持续运行表现 **待用户真机验收**。

## 用户部署后验收步骤
1. 部署 P2.3 后强制刷新独立 GitHub Pages 站点。页面应显示 `Prototype 2.3`，模型状态包含 `P2.3`；如仍为 P2.2，检查 `index.html` 和 JS 的上传路径及缓存。
2. 重点对比 **正面眼周/脸颊、45° 耳朵内外、侧面头颈、胸前和尾巴** 的短绒；查看耳内是否出现黑色覆盖、脸部是否闪烁或出现细刺。
3. 点击 `打招呼 / 走动 / 坐下 / 趴下休息 / 看向我`，观察毛片有无脱离、跳动或随骨骼错位；开关自主行为、专注模式，并观察正面/侧面切换。
4. iPhone Safari、Android Chrome、iPad／Mac/电脑分别观察是否能打开；手机连续运行 5–10 分钟查看卡顿、发热与后台恢复。
5. 把更新后的正面、侧面、耳缘与尾巴截图发回来，便于下一轮据实判断：是否应继续保留旧头部毛束或开展专业模型替换提案。

## 出现问题时如何回退
**回退到 P2.2（推荐）：** 在 GitHub 仓库从 P2.2 更新包恢复旧 `index.html`、`js/app.js`、`js/glb-renderer.js`（只恢复这 3 个已覆盖文件），可删除 P2.3 新增的 `js/face-fur.js` 及两份测试脚本；保留 P2.2 的 `js/fur-groom.js`、`js/renderer.js` 和原始 GLB。等待 GitHub Pages 重新发布并强刷浏览器。

**回退到 P2.1：** 再按 P2.2 自带说明恢复 P2.1 的相关文件。不要删除整个 `models/` 目录或擅自覆盖财务网站。

## 下一轮建议
先依据真实 P2.3 图片对外耳／头脸／胸前的软毛与旧装饰资产进行视觉判断；若存在结构性穿帮或程序化模型上限问题，先单独提出 P2.4 专业资产方案，得到明确确认后再重建 GLB。
