# Black Gold Cat P2.2 — 分层短绒毛流增量版本

## 变更基线与范围
- 唯一代码基线：用户提供的 `MMHVAULT-Cat-Companion-main.zip`，实际 P2.1。
- **没有修改 P2.1 原始 GLB**：仍使用 `models/black-gold-cat-p21.glb`（约 7.71 MiB）、两套 GPU skin、6 段 glTF 关键帧动画。
- **没有修改** MMHVAULT 主网站、Life Planner、Supabase、账户、交易及其他财务功能。
- 未更换猫的美术角色、耳朵、头部、动作骨骼或行为状态机。

## P2.2 真实技术改动
1. 新增 `js/fur-groom.js`：从原有蒙皮身体/尾巴基础网格生成两个贴身表面薄绒壳，及跟随表面切线/毛流方向的短三角毛片；每个新顶点保留/插值 skin 权重，跟随动画骨骼移动。
2. `js/renderer.js`：为薄绒壳单独添加 WebGL2 屏幕门控覆盖着色（有序抖动），为绒毛边界增加空间层次，避免普通半透明深度排序问题。此方案是**实时绒毛近似**，不等于专业离线毛发系统。
3. `js/glb-renderer.js`：停用 P2.0 四组长刺状毛片及 P1.6 旧蒙皮绒毛片的显示和 GPU 上传；停止绘制 P08 基础网格的第二段旧三角毛片，同时保留其第一段完整四足蒙皮表面。运行时追加新绒毛网格，使用与原始身体/尾巴相同的 skin palette。屏幕宽度低于 620 CSS px 时，仅绘制基础绒毛层。
4. `js/app.js` 和 `index.html`：升级页面展示与资源缓存版本至 P2.2，GLB 路径保留 p21，仅清理旧文案。
5. 新增 `tools/check-p22-fur.mjs`：可重复运行的离线 GLB/蒙皮/索引/动画一致性检查。

## 已执行的验证
- JS 语法检查：`node --check`，涵盖新增及修改 JS。
- P2.1 GLB 结构：2 skins、6 clips、权重和索引一致。
- 新增毛发：身体及尾巴各 4 层，顶点数限制 <= 65535，归一化蒙皮权重、骨骼 ID、索引检查通过。
- 使用无 GPU 的 WebGL API 模拟器测试了桌面与窄屏路径、GLB 解析、蒙皮状态以及五种动作状态下的渲染调用和资源释放；不等于真实 GPU 编译或显示测试。
- Chromium 对 `320 / 375 / 390 / 650 / 768 / 844 / 1440` px 宽度执行了静态响应式布局检查，没有横向溢出。
- **未通过真实 WebGL2/GPU 画面验证**：本运行环境的 Chromium 禁止启用 WebGL2，因此不能报告真实 FPS、视觉毛发质量、手机发热、穿模/动画质量已通过。
- 暂未运行 iOS Safari、Android Chrome 或真机长时压力测试。

## 部署后人工验收
1. GitHub Pages 打开旧 URL，强制刷新；右上角应显示 `Prototype 2.2`，模型状态含 `P2.2`。
2. 正面、三分之二角度、侧面、背面观察毛发是否更柔和、是否仍有硬刺/黑色边缘裂缝。重点看肩背、胸口、四肢和尾巴。
3. 验证「走动 / 坐下 / 趴下 / 打招呼 / 看向我」、自主行为开关、专注观看、点击、手机纵横屏。
4. iPhone Safari 和 Android Chrome 分别测试 5–10 分钟，看是否发生加载失败、明显卡顿、闪烁或发热。
5. 任何异常都请保留截图及浏览器机型信息，下一轮针对真实画面再精修。

## 边界与后续
这次解决的技术点是**替换毛发几何和绘制方式**，而不是单纯增加毛束数量或改颜色，也不是重建角色。旧角色拓扑及头/耳结构仍然是程序化原型，离确认的参考设定图还有距离。真正专业拓扑、UV、逐区域梳毛和动画重制应在收到下一轮实际画面后单独评估，遇到需要替换整套 GLB 的重大变更必须先获得用户确认。
